# 证据记录规范

- `OBS`：实际操作验证
- `OFF`：官方网页、帮助中心、发布说明或产品内说明
- `CASE`：公开客户案例或企业披露
- `MED`：可信媒体或独立分析
- `SOC`：公开社交平台、社区或应用商店反馈

每条记录至少包含证据 ID、产品、标题、来源类型、URL 或本地截图路径、观察日期、版本、摘要和支持的结论。

普通用户姓名、头像、联系方式和账号标识不得进入报告。社交内容以归纳和匿名摘录为主。

## 功能状态口径

- `已实测完成`：本轮在目标产品内独立完成了该动作。
- `存在但未执行`：本机界面或连接器可见，但尚未纳入统一任务独立验证。
- `官方宣称`：官方页面或帮助文档明确描述。
- `第三方报告`：媒体、社区或独立作者公开描述。
- `本次未发现`：本轮证据范围内没有找到；不得改写为“不支持”。
- `环境或权限阻塞`：功能入口存在，但被权限、组件、登录或环境阻断。

## 结论边界

- 三组产品各执行一次完整运行，因此“稳定性”只描述本次运行表现，不外推长期故障率。
- 产品内 Agent 对自身连接状态的描述不等于独立实测，统一测评会再次复核。
- 命名客户列表只证明公开关联，不自动证明部署范围或量化收益。
- 社区内容用于理解采用动因、痛点和市场叙事，不作为硬功能判定的唯一依据。
- 当前千问办公客户端没有名为 Auto 的选项；按用户决定使用“基础”并记录协议偏差。

## 控制界面能力口径

- `Computer Use` 只统计基于屏幕状态完成的桌面点击、键入、滚动、拖拽和跨应用操作；Python、Bash、CLI 和文件 API 单独统计。
- `Browser Use` 只统计真实浏览器页面中的导航、点击、输入、表单、下载和状态读取；WebSearch、WebFetch 与 general_search 属于搜索或抓取工具。
- `In-app Browser` 指 Agent 客户端托管或嵌入的浏览器环境。本轮最小实测只要求客户端内打开本机页面并读取标题；登录态、下载、弹窗和会话延续留作生产级验证。
- 产品内自测或连接器显示 Open 只能证明入口或环境可见，不能替代统一任务中的独立实测。
